Get anime episodes grabbed and imported as the right episode in a few minutes. The proxy sits between Prowlarr and Sonarr and rewrites a release only when it is sure about it. When it is not sure, it passes the release through unchanged, so Sonarr never does worse than it does today. It works for torrent indexers (Torznab) and usenet indexers (Newznab) alike.

```
Sonarr  ->  Courmap proxy (/nyaa, /animetosho, ...)  ->  Prowlarr  ->  your indexers
```

## Before you start

You need Docker (or Unraid), Sonarr v4 and Prowlarr, with the three containers able to reach each other by name. Then collect:

<Steps>

1. **Your Sonarr API key.** In Sonarr, open **Settings**, then **General**. Under **Security**, copy **API Key**. It goes into the proxy.

2. **Your Prowlarr API key.** In Prowlarr, open **Settings**, then **General**. Under **Security**, copy **API Key**. It goes into Sonarr.

3. **The Prowlarr ID of each anime indexer.** Prowlarr serves every indexer as its own feed at `http://prowlarr:9696/<ID>/api`. To find the ID, open **Settings**, then **Indexers** in Sonarr. Prowlarr has already added your indexers there with names ending in "(Prowlarr)". Open one, and the number in its **URL** is the ID: `http://prowlarr:9696/1/` means ID `1`.

   No Prowlarr indexers in Sonarr yet? Ask Prowlarr for the list instead; each entry shows `"id"` next to `"name"`:

   ```sh
   curl -s "http://<prowlarr-host>:9696/api/v1/indexer?apikey=<prowlarr-api-key>"
   ```

</Steps>

<Aside title="Container names only work on a shared network">
Addresses such as `http://sonarr:8989`, `http://prowlarr:9696` and `http://courmap-proxy:9797` use container names. Docker resolves those only between containers on the same user-defined network (a Compose project's network, or a custom network on Unraid). If your containers are on the default `bridge` network, or on different machines, use the host's IP address and published port instead, for example `http://192.168.1.10:8989`. Behind a VPN container such as gluetun, see [the full guide](/sonarr/#behind-a-vpn-container).
</Aside>

## 1. Run the proxy

You add one `INDEXER_<NAME>_URL` setting per anime indexer. `<NAME>` is a label you choose, written in capital letters, digits and underscores. It is **not** the Prowlarr ID. The proxy lowercases it and turns underscores into hyphens, and the result is the path Sonarr will use. The Prowlarr ID goes inside the value, in the URL.

For two indexers, Nyaa (ID `1` in Prowlarr) and AnimeTosho (ID `2`):

| Setting | Value | Address Sonarr uses |
| --- | --- | --- |
| `INDEXER_NYAA_URL` | `http://prowlarr:9696/1/api` | `http://courmap-proxy:9797/nyaa` |
| `INDEXER_ANIMETOSHO_URL` | `http://prowlarr:9696/2/api` | `http://courmap-proxy:9797/animetosho` |

A label such as `ANIME_TOSHO` would be served at `/anime-tosho`.

**A usenet indexer takes one more setting, its type.** For a usenet indexer (ID `3` in Prowlarr here), also set `INDEXER_GEEK_TYPE` to `newznab`. Torrent indexers need none. If you leave it out, the proxy works the type out from the indexer's first results, but setting it is the safe choice.

| Setting | Value | Address Sonarr uses |
| --- | --- | --- |
| `INDEXER_GEEK_URL` | `http://prowlarr:9696/3/api` | `http://courmap-proxy:9797/geek` |
| `INDEXER_GEEK_TYPE` | `newznab` | |

Proxy every indexer you use for anime, whether it carries only anime or regular TV as well. Indexers you never use for anime can stay as they are.

<Tabs syncKey="install">
<TabItem label="Docker Compose">

Add this service next to Sonarr and Prowlarr. In the same Compose file, it joins their network automatically.

```yaml
services:
  courmap-proxy:
    image: ghcr.io/courmap/proxy:edge   # the only tag for now, see the note below
    container_name: courmap-proxy
    restart: unless-stopped
    ports:
      - "9797:9797"                # the status page
    volumes:
      - ./courmap/data:/data       # downloaded data and the list of names it could not resolve
      - ./courmap/config:/config   # optional: a courmap-proxy.yaml with the same settings
    environment:
      # Lets the proxy read your series list.
      SONARR_URL: http://sonarr:8989
      SONARR_API_KEY: your-sonarr-api-key        # Sonarr's key goes here, not Prowlarr's

      # One line per anime indexer: INDEXER_<NAME>_URL.
      # <NAME> is any label you choose. It becomes the path (NYAA is served at /nyaa).
      # The number in the URL is the indexer's ID in Prowlarr.
      INDEXER_NYAA_URL: http://prowlarr:9696/1/api
      INDEXER_ANIMETOSHO_URL: http://prowlarr:9696/2/api

      # A usenet indexer (here Prowlarr's ID 3) also needs its type. Torrent indexers do not.
      # INDEXER_GEEK_URL: http://prowlarr:9696/3/api
      # INDEXER_GEEK_TYPE: newznab
```

If Sonarr and Prowlarr live in a different Compose project, the proxy has to join their network. `docker inspect sonarr --format '{{range $name, $_ := .NetworkSettings.Networks}}{{$name}} {{end}}'` prints its name; put that name in place of `media_default` below and keep everything else as above:

```yaml
services:
  courmap-proxy:
    # ...image, ports, volumes and environment as above...
    networks: [arr]

networks:
  arr:
    external: true
    name: media_default   # the network Sonarr and Prowlarr are on
```

Start it with `docker compose up -d courmap-proxy`.

</TabItem>
<TabItem label="Unraid">

<Steps>

1. Open the **Docker** tab and click **Add Container**. Leave **Template** empty, and switch on **Advanced View** at the top right so every field shows.

2. Fill in the form:

   - **Name**: `courmap-proxy`
   - **Repository**: `ghcr.io/courmap/proxy:edge`
   - **Network Type**: the custom network your Sonarr and Prowlarr use (for example **Custom: proxynet**). If they run on **bridge**, choose **bridge** and use IP addresses in every URL below.
   - **WebUI**: `http://[IP]:[PORT:9797]/`
   - **Extra Parameters**: `--user 99:100`, so its files belong to `nobody:users` like your other appdata

3. Click **Add another Path, Port, Variable, Label or Device** once for each item below, choosing the **Config Type** shown first:

   - **Port**: **Container Port** `9797`, **Host Port** `9797` (the status page).
   - **Path**: **Container Path** `/data`, **Host Path** `/mnt/user/appdata/courmap-proxy/data`.
   - **Path**: **Container Path** `/config`, **Host Path** `/mnt/user/appdata/courmap-proxy/config`.
   - **Variable**: **Key** `SONARR_URL`, **Value** `http://sonarr:8989`.
   - **Variable**: **Key** `SONARR_API_KEY`, **Value** your **Sonarr** API key.
   - **Variable**: **Key** `INDEXER_NYAA_URL`, **Value** `http://prowlarr:9696/1/api`.
   - **Variable**: **Key** `INDEXER_ANIMETOSHO_URL`, **Value** `http://prowlarr:9696/2/api`.
   - **Variable**, only for a usenet indexer: **Key** `INDEXER_GEEK_URL`, **Value** `http://prowlarr:9696/3/api`.
   - **Variable**, only for a usenet indexer: **Key** `INDEXER_GEEK_TYPE`, **Value** `newznab`.

   Give each a **Name** you will recognize later, such as "Sonarr URL".

4. Click **Apply**. If the status page later says the data folder is not writable, run `chown -R 99:100 /mnt/user/appdata/courmap-proxy` in the Unraid terminal.

</Steps>

<Aside title="About the :edge tag">
`edge` is the only image tag for now. It follows the main branch and is rebuilt on every change to the proxy. To stay on one build, use the matching `sha-<commit>` tag: the status page shows your build as `edge-` followed by the first seven characters of the commit, so `edge-1a2b3c4` is `ghcr.io/courmap/proxy:sha-1a2b3c4`. Versioned tags will appear once the first proxy release is cut.
</Aside>

Open the status page at `http://<your-host>:9797/`. Within a minute it should show a **Data version** and, next to **Sonarr**, how many series it found.

## 2. Add each proxy path to Sonarr

Sonarr talks to the proxy like it talks to any indexer. Torrent and usenet indexers are added as different types, so pick your tab. Choosing the wrong type gives results Sonarr cannot use.

<Aside title="Two different API keys">
The proxy holds your **Sonarr** API key (step 1). Sonarr holds your **Prowlarr** API key, in each indexer below. The proxy passes it on to Prowlarr.
</Aside>

<Tabs syncKey="protocol">
<TabItem label="Torrent (Torznab)">

<Steps>

1. In Sonarr, open **Settings**, then **Indexers**, click **+**, and choose **Torznab** under **Custom**.

2. Fill in:

   - **Name**: `Nyaa (Courmap)`
   - **URL**: `http://courmap-proxy:9797/nyaa`
   - **API Path**: `/api`
   - **API Key**: your **Prowlarr** API key
   - **Categories**: `5070` for an anime-only indexer like this one; leave it empty for an indexer that also carries regular TV
   - **Anime Categories**: `5070`
   - **Indexer Priority**: `10`

   `5070` is the standard Torznab category number for TV/Anime, which anime indexers file their releases under. Sonarr searches **Anime Categories** for series whose type is Anime and **Categories** for the rest, and an empty list means that kind of series is not searched at this indexer (Sonarr accepts an empty **Categories** as long as **Anime Categories** is set). Nyaa carries only anime and has no Prowlarr copy after step 3, so its Courmap copy also serves series typed Standard; for a general tracker, leave **Categories** empty so Prowlarr's copy keeps handling regular TV. **Indexer Priority** 10 beats Prowlarr's 25 when both copies return the same release.

3. Click **Test**. A green check means Sonarr reached Prowlarr through the proxy. Click **Save**.

4. Repeat for `http://courmap-proxy:9797/animetosho`, named `AnimeTosho (Courmap)`.

</Steps>

</TabItem>
<TabItem label="Usenet (Newznab)">

<Steps>

1. In Sonarr, open **Settings**, then **Indexers**, click **+**, and choose **Newznab** under **Custom**. (The named presets, such as NZBgeek, connect straight to the indexer; Custom lets you point it at the proxy.)

2. Fill in:

   - **Name**: `Geek (Courmap)`
   - **URL**: `http://courmap-proxy:9797/geek`
   - **API Path**: `/api`
   - **API Key**: the usenet indexer's own API key, or your **Prowlarr** API key if the feed comes from Prowlarr
   - **Categories**: leave empty (clear Sonarr's default 5030 and 5040)
   - **Anime Categories**: `5070`
   - **Indexer Priority**: `10`

   `5070` is the standard Newznab category number for TV/Anime, which usenet indexers use too. Sonarr searches **Anime Categories** for series whose type is Anime and **Categories** for the rest, so an empty **Categories** keeps this copy for anime only: regular series are still searched at Prowlarr's copy of the same indexer (step 3). Sonarr accepts an empty **Categories** as long as **Anime Categories** is set. **Indexer Priority** 10 beats Prowlarr's 25 when both copies return the same release. (If an indexer carries only anime, use `5070` in both lists.)

3. Click **Test**. A green check means Sonarr reached the indexer through the proxy. Click **Save**.

4. Repeat for each usenet indexer you proxy.

</Steps>

NZB downloads do not go through the proxy: each result's download link still points at the indexer, so Sonarr fetches it from there as before.

</TabItem>
</Tabs>

## 3. Keep Prowlarr's copies for regular TV

<Aside type="caution" title="Do not skip this step">
Prowlarr adds every indexer to Sonarr itself, as a copy named after the indexer with "(Prowlarr)" on the end, such as "Nyaa (Prowlarr)". Left alone, that copy and your Courmap copy both return the same anime release: it shows up twice, and the unrewritten one can be grabbed under its original name. The two copies must share the work instead: Prowlarr's for regular TV, Courmap's for anime.
</Aside>

Sonarr decides which copy a search uses by category: a series whose type is Standard is searched in an indexer's **Categories**, a series whose type is Anime in its **Anime Categories**, and an empty list means that kind of series is not searched there. How you split the work depends on the indexer:

| The indexer | Examples | What to do |
| --- | --- | --- |
| Carries regular TV and anime | most usenet indexers, many torrent indexers | **A.** Keep Prowlarr's copy for regular TV and stop it searching anime |
| Carries only anime | Nyaa, AnimeTosho | **B.** Remove Prowlarr's copy, so only the Courmap copy exists |

### A. Indexers with regular TV and anime

Leave Prowlarr's Sonarr app on **Full Sync** with no tags, and take anime out of what it sends to Sonarr:

<Steps>

1. In Prowlarr, open **Settings**, then **Apps**, then your **Sonarr** app, and turn on **Show Advanced** so the category lists appear.

2. Clear **Anime Sync Categories** (remove `5070`). Leave **Sync Categories** and **Sync Level** (**Full Sync**) as they are, and click **Save**.

3. Back on **Indexers**, click **Sync App Indexers**.

4. In Sonarr, open **Settings**, then **Indexers**, and open one of the "(Prowlarr)" copies: its **Anime Categories** is now empty. Do not change the categories there yourself: Prowlarr rewrites both lists on every sync, so make category changes in Prowlarr.

</Steps>

Prowlarr's copy now searches regular series only. It still counts anime as part of the TV category, though, so its RSS feed can return anime releases under their original names. Anime series are never searched there, but the same release can reach Sonarr from both copies. That is why the Courmap copy has a higher priority (10 against 25): when Sonarr has the same release twice, it takes the rewritten one.

### B. Anime-only indexers

Clearing **Anime Sync Categories** does not remove an anime-only indexer from Sonarr, because its anime category sits under the TV category. Remove its copy with a tag instead. Prowlarr's app tags only *include* indexers (an app with tags receives just the indexers sharing one of them), so tag the indexers that should keep a copy, and the app:

<Steps>

1. In Prowlarr, open **Indexers**. For each indexer Sonarr should still get directly (the indexers from A), click it, type `sonarr` in **Tags**, press Enter, and click **Save**. Leave the anime-only indexers untagged.

2. Open **Settings**, then **Apps**, then your **Sonarr** app. Type `sonarr` in **Tags**, check that **Sync Level** is **Full Sync**, and click **Save**.

3. Back on **Indexers**, click **Sync App Indexers**. Prowlarr removes from Sonarr every indexer without the `sonarr` tag.

4. In Sonarr, open **Settings**, then **Indexers**, and check that the "(Prowlarr)" copies of your anime-only indexers are gone.

</Steps>

If you have both kinds of indexer, do A and B together: clear **Anime Sync Categories**, tag the indexers from A, and tag the app. With only anime-only indexers, tag the app and no indexer.

## 4. Check that it works

Open an anime series in Sonarr that has a few episodes out, and click the person icon on an episode's row (**Interactive Search**). Results from your Courmap indexers show rewritten titles in the **Title** column, built from the series title in your own Sonarr:

| The indexer's original name | What Sonarr shows |
| --- | --- |
| `[SubsPlease] Spy x Family - 17 (1080p) [ABCD1234].mkv` | `Spy x Family S01E17 (1080p) [ABCD1234] [SubsPlease]` |

Usenet indexers look the same: an NZB result gets the same kind of rewritten title. A release Courmap was not sure about keeps its original name; Sonarr treats it exactly as it would without the proxy.

## What success looks like

On the status page (`http://<your-host>:9797/`):

- **Data**: a data version, and your Sonarr series count (roughly how many series you have in Sonarr).
- **Indexers**: one row per path (`animetosho`, `geek`, `nyaa`) with the **Protocol** (`torznab` or `newznab`, as you set it or as the proxy detected it), **Requests** counting up as Sonarr's RSS sync runs, **Rewritten** with the share of results the proxy renumbered, and **Passed through** with the reasons for the rest.
- **Regular series stay with Prowlarr's copy.** In an Interactive Search, a series whose type is Standard adds nothing to the **Requests** of your Courmap indexers, and an Anime series does. If a Standard series does, check that **Categories** is empty on the Courmap copy.

Names the proxy could not resolve are listed further down, with a block you can paste into a GitHub issue to help improve the data.

## Not using Prowlarr?

The proxy is not tied to Prowlarr: it sits in front of any Torznab or Newznab feed. Sonarr's request goes to the address in `INDEXER_<NAME>_URL` with Sonarr's query and API key added, and the results come back rewritten.

- **Jackett** works. This setup was tested end to end on 2026-10-19 with Jackett, Sonarr 4.0.20 and the proxy image: Sonarr's indexer test passed, its TVDB searches were translated into title searches Jackett understands, and `[Erai-raws] Spy x Family Season 2 - 05 [1080p]...` reached Sonarr as `SPY x FAMILY S02E05 [1080p] ... -Erai-raws`. What changes from the steps above:
  - **The feed address.** In Jackett, click **Copy Torznab Feed** on the indexer's row and add `api` to the end, so Nyaa becomes:

    ```yaml
    INDEXER_NYAA_URL: http://jackett:9117/api/v2.0/indexers/nyaasi/results/torznab/api
    ```

  - **The API key.** In Sonarr's indexer, **API Key** is your Jackett API key (shown at the top of the Jackett dashboard). The proxy passes it on to Jackett.
  - **Step 3 is simpler.** Jackett does not sync anything to Sonarr, so there is nothing in Jackett to change. For an indexer that also carries regular TV, keep the copy you added to Sonarr from Jackett and clear its **Anime Categories**; for an anime-only indexer, delete (or disable) it.
  - **Leave Jackett's title tweaks off.** Some Jackett indexers offer to "improve Sonarr compatibility" by adding season information to titles. Keep that off for indexers behind the proxy: Courmap resolves the original name.
- **Another Torznab feed**, such as a tracker's own Torznab API, works the same way: put its address in `INDEXER_<NAME>_URL`. If it needs a key other than the one Sonarr sends, set `INDEXER_<NAME>_APIKEY`.
- **Sonarr's built-in Nyaa indexer** cannot go through the proxy: it reads Nyaa's own RSS feed, not Torznab, so there is nothing for the proxy to sit in front of. Add Prowlarr or Jackett to use Courmap.
- **Usenet (Newznab) indexers** work the same way, straight from the indexer if you like: set `INDEXER_<NAME>_URL` to its API address (for NZBgeek that is `https://api.nzbgeek.info/api`, the base address plus `/api`), `INDEXER_<NAME>_TYPE` to `newznab`, and use the indexer's own API key in Sonarr (step 2, Usenet tab).
- **Sonarr's built-in Fanzub indexer** is its own type, neither Torznab nor Newznab, so it cannot go through the proxy.
